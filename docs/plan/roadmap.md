## 三條排序規則

1. **1a 與 1b 並行，但 1a 的設計餵 1b 的規格**：finding、strategy_run 這些物件要進 #608 的事件規格，所以 #602／#603／#604／#593 的**決策**先出，#608 v1 才定稿，實作再跟。
2. **2 需要 1a 的身分和 1b 的規格，不需要簽章**：改進迴圈依報表改 skill——報表輸入沒規格，迴圈優化的是雜訊；單機自用時操作者信自己的帳本，簽章可以晚。
3. **簽章在「對外宣稱」之前，不在「內部跑」之前**：對陌生人說「策略 X 每美元產出多」時收據要能驗——#609 是 3a／3b 的門票，不是 1a 的。

## 七項出口測試（第 0 段）

| # | 測試 | 量法 |
|---|---|---|
| 1 | 免接力 | 一張 ready issue 到合併，控制者除 promote／ratify 外零手動觸碰 |
| 2 | 可觀察 | 每條 lane 都是有 heartbeat 的 peer；沒有來源靜默死超過一個節奏 |
| 3 | 誠實帳 | 每張合併 PR 的成本可從帳本算出，measured／unmeasured 分開，模型是觀察到的 |
| 4 | 結構安全 | 審查者唯讀靠工具政策；面碰撞由 `claim check` 拒絕 |
| 5 | 吞吐 | 持續 3 條實作 lane；PR 開了就派審；綠 PR 閒置 < 1 小時 |
| 6 | 穩定 | CI 一週零假紅 |
| 7 | 自舉 | edda 用上述迴圈連續兩個 wave 造自己，操作者不救火——**操作者介入次數就是指標** |

2026-09-02 量測：0.5／7（只有「穩定」半項，#583 當天修）。
